# App review, 17 November 2026

## Scope

Reviewed the existing nine screen-mirroring commits and the rest of the app's
main behavior and failure paths. This includes source review, regression
tests, dependency audits, native builds and synthetic browser checks. It does
not establish real-phone or real-screen-capture validation.

| Area | Review focus |
| --- | --- |
| Pairing, auth, server and TLS | Token persistence, failed loads, PIN/QR/approval limits, HTTP parsing, origin/host/proxy checks, file access, certificate recovery |
| Input engine and native event posting | Held input ownership, release/disconnect/pause, modifiers, repeat, scroll/momentum, gestures, text and keyboard-layout mapping |
| Actions, Deck and storage | Shell opt-in and shutdown, action bounds, ordered saves, conflicts/undo, imports, settings persistence and backups |
| Native app | Host lifecycle, capture cancellation, permissions, speech, app catalog, audio, pasteboard restoration, updater, login item and settings flows |
| Phone app | Connection recovery, six tabs, gestures/keyboards, Deck editor, Apps/Media, voice cleanup, settings sync/copy/backup, service-worker caching |
| Build and distribution | CI/release scripts, signing/update configuration, version checks, cask copy, dependency notices |

## Confirmed issues fixed

1. **Unreadable device list destroyed phone pairing.** Token authentication now
   returns a retryable refusal rather than `unknown`. Remembered re-pairing
   cannot overwrite the unreadable file. Unsupported trust-file versions are
   preserved, and an explicit Forget All resets the store. The phone retains
   its token and offers Reconnect with instructions to reopen the Mac app.
   Covered by server, store, connection and component tests.
2. **Mismatched authority key broke HTTPS recovery.** A saved CA key and
   certificate are checked together before reuse. An unusable pair is replaced
   along with its leaf certificate. A regression test validates the recovered
   certificate chain. Replacement of the authority requires trusting its new
   certificate on devices; an intact authority remains unchanged.
3. **Held controls released too early.** The phone now counts shared mouse
   buttons and held media keys, and the core counts media holds across devices.
   One finger lifting or one device disconnecting cannot release another hold.
   Tests cover normal release, repeated cleanup, disconnect and pause.
4. **Ambiguous saved/imported IDs.** Deck validation rejects empty IDs,
   duplicate pages and duplicate buttons within a page. Custom-keyboard loading
   compares shortened IDs before reuse and rejects inherited object names as
   media keys. These cases have regression tests.
5. **Missing bundled notices.** App builds collect app, Sparkle, Rust, web and
   vendored notices into `ThirdPartyNotices.txt`. Upstream fallback sources are
   versioned and checked against recorded hashes. About opens the notices,
   packaging refuses a missing notice file, and a native test verifies the
   shipped resource. The generated file contains 232 dependency entries.
6. **Incorrect refresh regression test.** The previous test waited for a pong
   by discarding earlier messages, including the cached display-list answer it
   intended to check. It failed repeatedly here. It now preserves that answer
   and verifies both cached and pending-query paths.
7. **Incomplete feature descriptions.** About, the HTML description and the
   web manifest now include screen mirroring. General explains that viewing
   keeps the Mac display awake.

The original newest-HD-picture, display-refresh, UDP-send-error tolerance,
power assertion, initial lock-state, permission-request, permission-change,
naming and cask patches remain in place. The HD queue's encrypted transfer
test and corrected refresh test pass. Native lock, sleep and permission
behavior still needs the hardware checks below.

## Dependency follow-up

The production phone dependency audit found no advisories. The full audit still
reports two moderate findings in test tooling:

- [glob, GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4),
  fixed in 14.0.2, while the current chain resolves 13.0.7.
- [minimatch, GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249),
  fixed in 11.0.1, while the current chain resolves 10.2.6.

The compatible `@vue/test-utils` update to 2.6.0 passed the phone checks but
does not remove these transitive advisories. Forcing major-version overrides
was deferred. These packages are not in the production phone dependency tree.

RustSec checked 225 lockfile dependencies and found no vulnerability advisory,
with one unmaintained warning for `basic-toml` 0.1.10,
[RUSTSEC-2026-0374](https://rustsec.org/advisories/RUSTSEC-2026-0374).
It is reached through Askama's derive machinery and UniFFI binding generation.
There is no fixed upgrade reported by the audit database.

## Remaining release checks and improvements

- Exercise ScreenCaptureKit on a real Mac with iPhone/iPad and Android clients:
  permission grant/revoke, launch while locked, explicit lock/sleep, idle power,
  monitor removal/rotation, capture startup cancellation and Wi-Fi roaming.
- Test microphone dictation on actual phones with a trusted HTTPS certificate,
  interruption by calls/backgrounding, and languages with on-device support.
- Test offline home-screen launch on actual mobile browsers after an app update.
- Expand deterministic native-service tests by injecting capture, permission
  and speech adapters. Compilation and generated-frame tests leave OS callback
  ordering and permission-prompt behavior unexercised.
- Consider broader backpressure and cancellation tests for admitted asynchronous
  native work, including clipboard, volume and app actions. This review did not
  reproduce an exploit or a new failure in those paths.
- The first Screen Recording click after upgrading an older installation can
  still be silent if macOS already showed its prompt before the new requested
  flag existed; a subsequent click opens Settings. Validate this migration on
  a machine with existing permission history before changing the prompt flow.

The source remains at 0.8.1 with notes under Unreleased. Creating a 1.0.0
heading, choosing its summary and running `scripts/bump-version.sh 1.0.0`
remain release actions after hardware validation. No tag, push or publication
was performed by this review.
